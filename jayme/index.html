Project 01 / Operational Decision Support

Signal

Working Prototype

The Environment

High-volume restaurant and retail service operations generating large daily transaction logs and shift labor exports.

The Problem

Operators are flooded with raw daily exports from Toast POS and scheduling databases. Important override leaks, labor margin anomalies, and patterns of operational friction remain hidden inside thousands of spreadsheet rows.

What I Designed or Built

Signal, a local-first operational data validation and decision intelligence tool that digests unstructured HTML/CSV transaction records.

How the System Works

The system normalizes incoming POS logs, runs checks for data completeness, flags anomalies (such as off-hour manager overrides), computes confidence and severity scores, and generates a structured, prioritized checklist of issues for managers to review.

Human-Review / Safety Boundaries

Signal operates purely as a decision-support tool. It does not automate employee disciplinary actions, scheduling changes, or POS corrections; all flagged items require validation by a human general manager.

What the Project Demonstrates

Data normalization, pattern detection, rule-based auditing, and translating messy database files into clean, human-actionable summaries.

Potential Transferability

Any operational sector that exports regular transaction logs (e.g. warehouse inventory logs, logistics dispatch logs, retail cashier summaries) and requires prioritized human-in-the-loop review.

Relevant to: Product operations, data quality, data validation logic, restaurant audits, operational decision support.

Project 02 / Intelligent Asset Organization

GenSort

Working Prototype

The Environment

Local digital media workspaces managing large volumes of visual assets, generated images, brand photography, and source catalogs.

The Problem

Organizing, labeling, reviewing, and comparing thousands of image files is extremely slow. Uploading library contents to third-party cloud tools introduces privacy issues, compliance risks, and data control loss.

What I Designed or Built

GenSort, a desktop-focused local-first asset manager dashboard featuring smart folders and metadata lineage controls.

How the System Works

GenSort scans local directories to build an offline metadata catalog. It maps similarity structures, indexes color profiles, traces generative prompt-and-seed lineage, and scores assets based on project readiness parameters.

Human-Review / Safety Boundaries

The dashboard is 100% offline. No asset data or metadata leaves the local computer. Reclassification and file relocation are suggested to the user, but the system never moves or deletes files without explicit human confirmation.

What the Project Demonstrates

Local-first application development, desktop system design, directory indexing, and structured metadata schemas.

Potential Transferability

Beyond images: The underlying directory indexing and comparison logic can be adapted to manage and index high-volume text databases or source-code archives.

Relevant to: Digital asset management, local-first software, prompt lineage, folder structure design, desktop architectures.

Project 04 / Information Provenance

Record Integrity & Traceability

Concept Architecture

The Environment

Multi-source archival databases and collaborative document stores where data authenticity and original provenance must be audited.

The Problem

Lack of file-level verification allows undetected post-import edits, unverified transcript versions, and disconnected file links, compromising the integrity of the data store.

What I Designed or Built

A traceability and integrity framework enforcing strict cryptographic and schema validation standards on imports.

How the System Works

It validates record inputs against unified schemas, assigns stable identifiers, computes SHA-256 hashes for every file, tracks verification states, and triggers alerts if files are modified post-import.

Human-Review / Safety Boundaries

Disclosure: Integrity controls can identify changes and preserve provenance. They do not independently establish authorship, legal admissibility, or factual truth.

What the Project Demonstrates

Cryptographic validation, database schema integrity, digital chain of verification, and audit trail design.

Potential Transferability

Digital archive storage, regulatory compliance archives, verification logs, and supply-chain shipping logs.

Relevant to: Data quality, information security, database schema design, and compliance systems.

Project 05 / Textual Discrepancy Spotting

Contradiction Finder

Functional Demonstration

The Environment

Textual verification workflows analyzing transcripts, witness statements, and long-form records.

The Problem

Manually comparing statements made across multiple pages or dates to spot factual discrepancies is tedious and error-prone.

What I Designed or Built

A semantic contradiction finder script and UI mockup designed to highlight statement differences.

How the System Works

The parser tokenizes text inputs, extracts key assertions based on entity targets, clusters them by topic, and highlights opposing claims (e.g. conflicting times or dates) in a side-by-side view.

Human-Review / Safety Boundaries

Disclosure: The system only flags semantic variance for human evaluation. It does not judge intent, verify truth, or assume deception. Fictional demo inputs only.

What the Project Demonstrates

Natural language parsing pipelines, semantic comparison UI design, and focused verification queues.

Potential Transferability

Factual checking in journalism, policy auditing, customer chat history audits, and research literature reviews.

Relevant to: Natural language systems, workflow optimization, content audit, case management.
